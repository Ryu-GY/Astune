## T701

`scripts/verify-tests.mjs`가 Prisma SQLite 클라이언트 생성, 천체력 사전 검사, TypeScript 테스트, Python 테스트, 타입 검사를 순서대로 실행합니다. 오류를 만나면 즉시 중단합니다. TypeScript 파일 목록을 Node에서 직접 열거해 Windows와 Linux 셸의 glob 차이를 피합니다. 검증 프로세스의 DB 주소는 임시 파일로 덮어쓰며 실제 DB를 migrate하거나 seed하지 않습니다.

기존 시간대·DST·대표 별 계산·규칙 선택·API 어댑터·DB 게시 테스트를 포함합니다. 과거 DB 마이그레이션 fixture는 당시 스키마의 컬럼으로 생성하도록 고쳤습니다. 게시 실패의 롤백 검사는 성공 감사 기록과 별도로 남기는 실패 감사 기록을 구분해 검증합니다.

`.github/workflows/tests.yml`에 공식 Actions 커밋을 고정한 PR/main/develop 검증을 추가했습니다. **이 기록은 로컬 실행 결과이며 GitHub Actions에서 실제 실행한 결과는 아닙니다.** 새 CI 환경에서는 선택적인 Hipparcos 원본 재생성 비교 1개가 원본 부재로 생략될 수 있습니다. 성표 무결성과 실제 Skyfield 계산은 실행되며 천체력 부재는 실패로 처리합니다.

## T702

`tests/storage-permissions.integration.test.ts`는 9개 하위 시나리오와 상위 테스트 1개로 구성됩니다. 임시 SQLite에 합성 사용자·세션을 만들고 실제 Better Auth의 쿠키 서명 검증과 세션 조회, Next.js 핸들러, 서비스·Prisma 트랜잭션을 통과시킵니다. Python 위치·계산 응답만 고정합니다.

- 공개 위치/preview 결과와 비저장 동작
- 저장·목록·상세·프로필·관리자 API의 401, 일반 사용자의 관리자 API 403
- 개발용 헤더와 쿠키 서명 위조, 만료·폐기·로그아웃 세션 차단
- 소유자의 저장·상세 복원·페이지 분할·프로필 재사용, 타인 및 관리자의 개인 리딩 접근 차단
- 잘못된 날짜·좌표·시간대·페이지 입력, 교차 출처, JSON 외 요청, 계산 실패 시 부분 저장 방지
- 출생시간 미상 표시의 저장·복원, DB 관리자 권한 회수의 즉시 반영
- 관리자 입력 오류, 규칙 생성·수정·게시, 게시 실패 시 이전 버전 유지, 단일 게시 버전 및 감사 기록
- 규칙 교체 이후 새 preview 변경과 기존 저장 리딩 보존, 저장 리딩 조회 시 재계산 없음

테스트가 발견한 관리자 버전 생성 오류도 수정했습니다. `null`, 숫자·배열 이름, 객체 설명을 보내면 `.trim()` 예외로 500이 나던 경로를 입력 검증 400으로 처리합니다. 관리자 규칙 PUT도 공통 규칙 스키마로 검증하도록 정리했습니다.

Google OAuth 제공자의 실제 로그인 화면과 PostgreSQL에서의 동작은 이 테스트의 범위에 포함하지 않습니다. 실행 방법은 [테스트 안내](../../tests/README.md)에 있습니다.
