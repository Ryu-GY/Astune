# T801–T803 배포 검증

검증일: 2026-10-13. 기본 경로는 브라우저 → Vercel Next.js → Render FastAPI/Skyfield → TypeScript 해석 → Neon PostgreSQL 저장이다.

## T801: 환경 재현과 데이터 이관

- Node 24.21.0, Python 3.11, uv 0.11.6, Next.js 16.4.0, Prisma 6.19.3, Vercel CLI 63.1.2.
- 분리한 작업 복사본에서 `npm ci`, PostgreSQL Prisma 생성, 운영 빌드 성공. 실행 중인 로컬 개발 서버의 SQLite 클라이언트는 교체하지 않았다.
- Python 123개, TypeScript 50개 테스트 통과. 초기 seed의 5초 트랜잭션 제한은 원격 DB 지연을 고려해 60초로 조정하고 관련 7개 테스트를 재검증했다.
- [develop 56b9ccc CI](https://github.com/Ryu-GY/Astune/actions/runs/38359965653)에서 새 Ubuntu 환경의 잠금 의존성 설치, DE421 준비, 전체 테스트, 운영 빌드, PostgreSQL 17 Docker Compose 검증 모두 성공.
- 합성 SQLite → 실제 PostgreSQL의 전체 테이블 왕복 일치, 날짜/BigInt, 덮어쓰기 거부, SQL 제약 확인. 테스트 후 전용 컨테이너·볼륨 제거.
- 이 Windows PC의 Docker Desktop은 시작 시 `sailor-ingest.sock` 접근 오류가 있어 로컬 컨테이너 실행은 확인하지 못했다. Compose 재현성은 위의 깨끗한 Linux CI에서 확인했다. 개인 Docker 데이터를 초기화하거나 삭제하지 않았다.

## T802: 수동 배포

- 웹: https://astune.vercel.app — Vercel `ryu-gayoungs-projects/astune`, 운영 함수 `sin1`.
- 계산: https://astune-api.onrender.com — Render Free, Singapore, Docker. 첫 성공 배포 소스 `ce8a173`, 빌드·기동 1분 17초.
- DB: Neon `astune-db`, Free, Singapore. PostgreSQL 초기 마이그레이션과 게시 해석 규칙 seed 적용 성공.
- Google OAuth의 실제 운영 원본·콜백 등록 후 정상 로그인 확인. 운영 세션 비밀값을 로컬과 분리하고 개발 헤더 인증은 비활성화했다.
- Render `/health`, `/ready` 200. 내부 키 없는 계산은 401, 유효한 키가 있으면 200. 운영 `/docs`는 404. 천체력·성표·시간대 데이터가 컨테이너에 포함된 상태에서 동작한다.
- Vercel Git 연결 없음, `git.deploymentEnabled=false`; Render Auto-Deploy Off. GitHub Actions는 검증만 실행한다.

## T803: 공개 주소 검증

- `node scripts/check-deployment.mjs https://astune.vercel.app`: 10개 확인 통과. 공개 페이지, 비로그인 저장/보관함/관리자 차단, 미래 날짜 422, 서울 검색, 실제 천문·해석 5개 영역, 시간 모름 경고, 반복 계산.
- 브라우저에서 실제 Google 로그인, `배포 검증용 예제` 계산, 리딩·출생 프로필 저장, 보관함의 Capella 결과와 전체 해석 재조회 성공. 검증 예제는 실제 출생 정보가 아니며 계정 보관함에 남겨 두었다.
- 타인 리딩 접근·관리자의 개인 리딩 접근 차단·세션 폐기·역할별 쓰기 권한은 별도 격리 DB 통합 테스트에서 확인했다. 운영 DB에 임시 관리자나 직접 만든 인증 세션을 주입하지 않았다.
- 초기 OAuth 설정 중 만료된 요청의 `State not found` 오류 1건이 있었다. 주소 등록 후 새 요청으로 실제 Google 로그인이 성공했다.
