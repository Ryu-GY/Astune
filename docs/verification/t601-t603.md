## 자동 검증

- TypeScript 전체: **36 통과** (`npm test`, 분리 복사본).
- Python 전체: **120 통과, 선택 검사 1 생략**. 실제 로컬 DE421을 사용했다. 생략한 항목은 원본 `hip_main.dat` 전체 재생성 검사이며, 분리 복사본에 대용량 원본을 복사하지 않았기 때문이다. 천문 계산·회귀·DST·오류·추적 검사는 모두 실행했다.
- Next.js 운영 빌드: `next build --webpack` 통과. TypeScript 및 정적 페이지 생성 완료. 중첩 검증 폴더의 lockfile 때문에 workspace root 안내가 출력되었으며 빌드 오류는 없었다.
- `scripts/check-api-contract.mjs`: 실제 HTTP **13개 사례 통과**.
- `scripts/check-request-policy.mjs`: 실제 HTTP **20개 요청 통과**. 정상 계산, 미래 날짜, 잘못된 날짜·오프셋·숫자 타입, IANA 시간대, DST 중복/누락, 1800년 및 0001년 경계를 양쪽 서버에서 비교했다.
- 저장 테스트: 형식 오류·미래 날짜는 내부 서버 호출 전 차단. DST·천체력 오류·계산 서버 장애가 발생하면 리딩과 출생 프로필의 DB 행 개수는 모두 0이다.

## 전체 흐름

사용자가 출생 정보를 제출하면 브라우저 → Next.js 검증 → FastAPI 시간 변환·실제 천체력 계산 → TypeScript 해석 → 결과/복구 안내 화면으로 이어진다.

| 경계 | 확인 결과 |
| --- | --- |
| 화면 → 공개 API | 브라우저에서 미래 날짜 제출 시 “미래의 출생 날짜는 사용할 수 없습니다. 출생지 시간대의 오늘 또는 이전 날짜를 입력해 주세요.” 표시 |
| 공개 API → 내부 API | 성공 및 DST 오류에 동일한 `X-Request-ID`가 양쪽 로그와 응답 헤더에 존재 |
| 내부 API → 데이터 | 로컬 Hipparcos 성표와 DE421로 Capella 계산 및 범위 밖 날짜 거절 |
| 응답 → 화면 | 날짜를 1995-05-05로 수정하고 시간 모름 선택 시 Mirfak 참고 결과와 낮 12시 경고 표시. 브라우저 콘솔 오류·경고 없음 |
| 로그 | 이름·출생 일시·좌표·시간대·검색어·쿠키·토큰·원문 예외가 없음을 동시 요청 및 실패 테스트로 확인 |

실제 정상 요청의 같은 ID `contract-8bea81e5-cb1b-478e-866c-0386eed89cc2`에서 Next.js는 총 30.445ms(검증 15.212, 내부 HTTP 계산 13.717, 해석 0.933), Python은 총 11.899ms(위치 0.052, 검증 0.032, 계산 9.9)를 기록했다. 이는 한 요청의 관측값이며 성능 백분위 수치는 아니다.

## 재현

두 서버 실행 후:

```powershell
npm test
npm run backend:test
npm run test:api
node scripts/check-request-policy.mjs
```

별도 포트 검증:

```powershell
node scripts/check-request-policy.mjs --next=http://127.0.0.1:3002 --python=http://127.0.0.1:8002
```

상태 코드 변경: FastAPI 형식 검증은 기존 422에서 **400**, 공개 계산 실패는 기존 503에서 내부 서버와 동일한 **500**으로 맞췄다. 응답 필드·날짜 정책·배포 로그 주의사항은 [API 계약](../api.md)을 따른다.
