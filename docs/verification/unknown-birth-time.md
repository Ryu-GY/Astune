# 출생 시간 모름

사용자가 `태어난 시간 모름`을 선택하면 시간 입력과 DST 중복 시각 선택을 비활성화합니다. 날짜·도시·좌표·시간대는 계속 필요합니다. 화면과 API 모두 해당 날짜의 현지 낮 12:00:00을 참고 계산 시각으로 사용합니다. 이전에 입력한 실제 시각이나 DST fold는 참고 계산에 사용하지 않습니다. 선택을 해제하면 이전 시각을 복원합니다.

낮 12시는 실제 출생 시각의 추정치나 하루 전체의 대표값이 아닙니다. 하루 중 후보를 탐색하는 기능도 아닙니다. 입력·결과 화면에 다음 경고를 표시합니다.

> 출생 시간을 몰라 정확한 대표 별을 확정할 수 없습니다. 낮 12시를 기준으로 계산한 참고 결과이며, 실제 별과 해석·점수는 달라질 수 있습니다.

결과 제목·별·점수와 상세 계산 시각을 참고 결과로 표시하고, 브라우저 보관함에도 `시간 모름`과 경고를 유지합니다. 기존의 시간을 아는 리딩은 이전과 같이 읽습니다.

## API와 저장

Next.js 미리보기 입력에 `birthTimeUnknown: true`를 추가합니다. `birthAtLocal`에는 `1995-05-05`처럼 날짜만 전달할 수 있습니다. 시각이 함께 오더라도 서버가 현지 12시로 정규화합니다. 분리 입력인 `birthDate` 형식에서는 `birthTimeLocal`을 생략할 수 있습니다. 알 수 없는 시간대를 UTC 등으로 대체하지 않으며, 유효하지 않은 날짜·천체력 범위 밖 날짜·건너뛴 현지 날짜는 계속 거절합니다.

응답의 `input.birthTimeUnknown`과 `calculationNotice`에 불확실성과 기준 시각·경고가 들어갑니다. Python 계산 API에는 이 정규화된 참고 순간을 전달합니다. DB 리딩 저장 시에는 `interpretationMetaJson`에도 표시와 경고를 기록합니다. 출생 프로필 스키마에는 시간 모름 필드가 없으므로 참고 리딩을 실제 시각의 출생 프로필로 만들거나 연결하는 요청은 거절합니다. 현재 화면의 이 기기 리딩 보관은 사용할 수 있습니다.

## 검증

`tests/unknown-birth-time.test.ts`: 날짜 전용 입력과 두 API 입력 형식, 서버의 12시 정규화, 기존 시각·DST 제거, 잘못된 날짜·불리언·프로필 저장 차단, 실제 계산 함수에 전달되는 입력과 결과 경고, 브라우저 저장·재로드 및 기존 리딩 호환성을 검사합니다.

업로드 대상의 독립 스냅샷에서 TypeScript 테스트 15개와 Next.js 프로덕션 빌드를 통과했습니다. 프로덕션 서버를 별도 로컬 포트로 실행해 시간 모름 체크 → 시간 입력 비활성화 → 경고 → 참고 리딩 생성 → 보관 → 새로고침 → 경고·기준 시각 유지까지 확인했습니다. 선택 해제 시 이전 15:00 입력도 복원됩니다. 사용자 개발 화면과 다른 포트의 보관함에서 합성 입력만 사용했습니다.

1995-05-05 / 서울 / 최대 등급 2.0의 예시에서 현지 12시 기준 Mirfak 결과를 반환하며, 실제 출생 시각을 확정했다는 뜻은 아닙니다.
